# 完整运行流程

更新：2026-10-22。本文件说明当前统一 chat 入口的运行方式，业务目标见 [业务报告](business-results.md)。

## 1. 指定论文与目标

运行 chat，选择已登记论文或提供本地 PDF，描述本次想理解什么。表达可以不准确；Agent 可以询问澄清，也可标明暂定假设。程序复用可用材料，必要时归档和解析，建立论文及内容版本引用。

当前只处理明确指定的一篇论文。并不提供脱离论文的通用聊天、任意网络搜索或多论文自动研究。

## 2. 形成规划

程序固定加载 agent-policy、材料准备及规划说明，提供画像、框架、首页、章节标题和读取工具。模型决定是否补读或澄清，再提交结构化规划。程序检查材料版本、可选行为和必经 verification，保存 planning 片段。

规划保存目标、材料编号和候选步骤，不把路径写死。下一行为选择时再次结合真实进展判断。

## 3. 自主选择行为并交互

调度模型得到当前规划、已完成行为的实际记录摘要、用户输入及行为目录，输出下一行为与理由。执行器加载该行为完整说明。可选阅读、探讨、问答、知识记录；正常完成前必须理解验证。

行为可补读论文、查询知识点、获取本次学习允许的完整记录、讲解或提问。需要用户时暂停，不生成用户答案。终端中写多行，独占一行 `.` 提交。

模型提出候选记录时展示摘要，用户输入“保存”才正式提交；输入其他文字可继续修订。保存后控制器自动接回选择下一步，用户无需复制阶段编号。

用户可以 :do 指定行为，:end 请求进入验证。切换时未提交行为的对话仍留在运行记录，未保存候选不会混进正式成果。

## 4. 理解验证

根据当前规划与上一轮缺口，模型提出若干问题。程序分配题号，保存真实原始回复；模型给每题判断、参考答案和反馈。没有真实回答、漏评题目、把部分正确声称全部通过，都不能提交。

评分仍是模型判断，代码不声称能证明技术结论或用户理解完全正确。用户可以要求解释和修订候选。

验证结果保存成问答记录，不新增第十一类信息。

## 5. 结果复盘与新版规划

控制器自动运行复盘。reason 由模型根据实际问题和回答生成；是否达到目标取自正式验证，题号和真实记录关联由代码核对。result 片段列出本轮实际使用或创建的七类记录，不编造修改。

未通过则保留原目标与旧版结果，自动形成下一版规划，再继续选择行为。各版共享 study_id、revision 递增。模型若需要澄清，会回到同一终端等待。

每轮仍要真实学习与回答，不存在没有用户参与的无限答题循环。全会话 API 上限贯穿各版，子任务另有上限。

## 6. 结束或继续

通过后展示 reason 并询问是否结束。用户输入“结束”才标为 completed；输入“继续”回到行为选择。

:pause 保留进度并退出；:stop 明确提前退出，标为 ended_early，不能冒充通过。正常结束必须已有当前验证和学习结果。单个行为的保存不是整次学习结束。

## 产物位置

正式材料和产物统一见 [data/README.md](../data/README.md)。规划与结果属于同一类学习笔记，分别存文件并通过 plan_id 关联。行为产物带 plan_id；知识笔记关联知识点。画像和框架只读。

运行状态在 runs/chats，子任务、模型候选和快照在 runs/planning、runs/behaviors、runs/reviews。runs/learning 维护整个 study_id 的当前结束状态；不替代正式 result。

## 恢复与失败

chat --resume CHAT_ID 会恢复等待中的真实问题、候选或结束选择。尚未提交的终端文字不会保存。

失败、截断、达到次数上限或中断中的可能计费请求不自动重试。运行现场保留；恢复检测到未完成调用或提交时会停止，不盲目重发。被停止的会话目前没有自动修复/加预算入口，需检查对应状态或明确开始新会话。

只允许一个统一 chat 写入同一数据目录；不要同时运行其他写入命令。普通批量写入失败会回滚本次新文件，断电级事务与跨进程全局数据库锁仍未实现。
