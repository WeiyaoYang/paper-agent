# 阅读行为

标识：reading。状态：已接入单行为入口、交互、候选记录和本地结束保存；已由统一 chat 入口按实际目标自主选择。

## 用途与选择

根据用户目标读取并解释论文片段，整理理解重点与遗留问题。 Agent 或用户可选择该能力，不是每次学习的必经步骤。具体开展方式由模型结合用户目标、画像和材料判断，不规定固定教学步骤。

## 输入

明确指定的论文与本次请求；画像、知识框架作为只读上下文。程序提供首页、材料版本和按需读取能力。当前不会自动检索历史问答或读取其他论文，已有讨论可由用户在请求或回复中提供。

## 可用工具与交互

- read_paper_pages：按需读取这篇论文的一至三页，得到正文、定位块及限制。
- talk_to_user：展示讲解、观点、问题或反馈，然后等待真实用户回复；没有固定问题数量。
- find_knowledge_points：按名称或别名查询已有正式知识点，帮助复用标识。
- propose_record：按当前行为的候选结构整理已发生的内容，交给用户审阅，暂不写入正式目录。

等待时不编造用户发言。未理解的问题可以保留，不为了结束而强行判断已经掌握。用户可以通过 reply 继续讨论或要求修订候选；需要结束时先整理候选，再由用户本地 finish 保存。暂停保留运行状态，不把暂停当作结束。

## 结构与保存

候选结构使用 schemas/reading-record.schema.json：scope、summary、key_points、sources、unresolved_questions。模型只填写内容，编号、时间、运行标识、论文和版本关联均由程序填写。

sources 中每项为 paper_id、paper_content_id、pdf_page、block_id（可为空）、quote。仅引用实际提供或读取的页面；程序检查对应关系和引文是否存在。没有材料依据时可以留空，并在内容中明确这是解释、观点或待验证信息；不能把模型解释伪装成论文原句。

阅读、问答、探讨记录自动附入真实 messages，不允许模型重写对话冒充用户。模型摘要和反馈仍需用户审阅，结构检查不能保证语义正确。知识记录产生关联的知识点和知识笔记；同名或明确别名匹配时复用知识点，歧义时不强行合并，笔记和新知识点保持 unverified。

finish 不调用模型；成功后返回正式记录路径，可用 run_id 追溯原始交互。本行为不直接汇总学习结果，由统一入口的 learning-review 收集关联产物，不改变个人画像和知识框架，不执行最终理解验证。

统一入口会自动传入 plan_id 及本次真实学习记录摘要，必要时可用 read_learning_record 读取允许的完整记录。候选确认保存后自动回到调度，无需用户复制子任务编号。
